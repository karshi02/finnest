## สรุป

**คะแนนรวม: 6.5 / 10**: ใช้งานส่วนตัวได้ แต่ยังไม่ควรปล่อยให้คนอื่นใช้

เป็น PWA ไฟล์เดียว เก็บข้อมูลใน `localStorage` ฟีเจอร์ครอบคลุมดี (บันทึกเวท, คาร์ดิโอ, นาฬิกาพัก, stopwatch, โซนหัวใจ, เครื่องคำนวณ 4 ตัว, แผนรายสัปดาห์) ทำงานออฟไลน์ได้ และบางจุดเขียนมาอย่างรอบคอบ เช่น ฟังก์ชัน `esc()` กัน XSS, `todayStr()` ใช้เวลาท้องถิ่น และนาฬิกาที่อิง `Date.now()` จึงไม่คลาดเมื่อแท็บอยู่เบื้องหลัง

จุดอ่อนหลักมี 3 อย่าง:
1. **ข้อมูลหายง่ายและกู้คืนไม่ได้** เพราะไม่มี export/backup และถ้า JSON เสียแอปจะเปิดไม่ขึ้น
2. **แก้หรือลบประวัติไม่ได้** ถ้าบันทึกผิดก็ต้องทนอยู่กับข้อมูลนั้นตลอดไป
3. **ไม่มีตัวติดตามความก้าวหน้ารายท่า** ซึ่งเป็นเหตุผลหลักที่คนใช้แอปเวท

| ฟีเจอร์ | 7.5 | ครอบคลุม แต่ขาด PR, ความก้าวหน้ารายท่า และการแก้ไขข้อมูล |

## ต้องแก้ (บั๊ก / ความเสี่ยง)

เรียงจากสำคัญมากไปน้อย

### 1. ข้อมูลเสียแล้วแอปเปิดไม่ขึ้น (สูง)
`index.html:812` เรียก `JSON.parse(localStorage.getItem('fittrack') || '{}')` โดยไม่มี try/catch ถ้าข้อมูลเสีย (เช่นเขียนค้างกลางทาง หรือ extension ไปแก้) สคริปต์จะหยุดตั้งแต่บรรทัดนี้ ทำให้ทุกหน้าใช้งานไม่ได้
**แก้:** ครอบด้วย try/catch ถ้า parse ไม่ผ่านให้สำรองค่าเดิมไว้ที่ key อื่นก่อน แล้วค่อยเริ่ม state ใหม่

### 2. ไม่มี export / import ข้อมูล (สูง)
ข้อมูลทั้งหมดอยู่ใน `localStorage` ของเบราว์เซอร์เดียว ข้อมูลจะหายทั้งหมดถ้าล้างข้อมูลเว็บ เปลี่ยนเครื่อง หรือ iOS ลบข้อมูลของ PWA ที่ไม่ได้เปิดนาน
**แก้:** เพิ่มปุ่ม export เป็นไฟล์ JSON และปุ่ม import กลับ (ดูหัวข้อ "ควรเพิ่ม")

### 3. Chart.js โหลดจาก CDN โดยไม่ pin เวอร์ชัน (สูง)
`index.html:15`: `https://cdn.jsdelivr.net/npm/chart.js` จะได้เวอร์ชันล่าสุดเสมอ ถ้า Chart.js ออก major version ใหม่ที่เปลี่ยน API กราฟอาจพังได้เองโดยไม่ได้แก้โค้ดอะไร นอกจากนี้ถ้าเปิดแอปครั้งแรกตอนออฟไลน์ `Chart` จะเป็น undefined และ `renderDashboard()` จะ throw ตอนโหลด (`index.html:1466`)
**แก้:** pin เวอร์ชัน (เช่น `chart.js@4.4.x/dist/chart.umd.min.js`) ใส่ SRI hash หรือดาวน์โหลดมาเก็บในโปรเจกต์แล้วใส่ไว้ใน `SHELL` ของ `sw.js` และเช็ก `typeof Chart` ก่อนวาดกราฟ

### 4. Input ติดลบหรือใหญ่เกินผ่านการตรวจ (กลาง)
- `addWeightSet` (`index.html:987`): ถ้า reps = -5 จะผ่าน `!reps` ได้ ทำให้ volume ติดลบ ถ้า sets = 10000 ลูปจะ push 10,000 แถวและแอปค้าง แอตทริบิวต์ `min`/`max` ใน HTML ไม่ได้บังคับค่าที่อ่านผ่าน JS
- `calc1RM` (`index.html:1417`): สูตร Brzycki `36 / (37 - r)` ถ้า r ≥ 37 จะได้ Infinity หรือค่าติดลบ
- `logCardio` และ `saveQuickLog` ยังรับระยะเวลาติดลบได้

**แก้:** clamp ค่าใน JS ทุกจุด เช่น `reps` 1–100, `sets` 1–20 และ `r` 1–30

### 5. Set ที่ค้างไว้ข้ามวันถูกบันทึกเป็นวันที่ผิด (กลาง)
`state.todaySets` ถูกเก็บถาวร ถ้าเพิ่ม set ไว้เมื่อวานแต่ลืมกด "บันทึก Session" แล้วมากดวันนี้ `saveSession` (`index.html:1040`) จะใช้ `new Date()` เป็นวันที่ของ session ทำให้ข้อมูลไปตกอยู่วันนี้
**แก้:** ใช้ `ts` ของ set แรกเป็นวันที่ของ session หรือเตือนเมื่อพบ set ที่ค้างจากวันก่อน

### 6. รูปแบบวันที่ปนกัน (กลาง)
- `sessions` จาก `saveSession` เก็บเป็น ISO เต็ม (`2026-10-04T10:00:00.000Z`) แต่ข้อมูลจาก quick log และ cardio เก็บแค่ `2026-10-04`
- `new Date('2026-10-04')` ถูก parse เป็นเวลา UTC เที่ยงคืน ในไทยจึงยังได้วันถูก แต่ถ้าผู้ใช้อยู่ในโซนเวลาติดลบ (เช่นสหรัฐฯ) วันจะเลื่อนถอยไป 1 วัน
- `renderWeeklyChart` (`index.html:889`) ตั้งหัวข้อว่า "สัปดาห์นี้" แต่จริง ๆ คำนวณจาก 7 วันย้อนหลังแบบ rolling และนับรายการที่มีวันที่ในอนาคตด้วย เพราะ `diff` ติดลบก็ยังผ่านเงื่อนไข `< 7`

**แก้:** เก็บวันที่เป็น `YYYY-MM-DD` ตามเวลาท้องถิ่นทุกที่ เขียน helper `parseLocalDate()` และเปลี่ยนหัวข้อเป็น "7 วันล่าสุด" หรือคำนวณตามสัปดาห์จริง

### 7. เสียงแจ้งเตือนนาฬิกาพัก (กลาง)
`beep()` (`index.html:1123`) สร้าง `AudioContext` ใหม่ทุกครั้งที่ดังและไม่เคยปิด ใช้ไปนาน ๆ จะสะสม context ค้างไว้ อีกปัญหาคือ context ที่สร้างตอนหมดเวลาไม่ได้เกิดจากการกดของผู้ใช้ เบราว์เซอร์มือถือจึงอาจ suspend ไว้ ทำให้ไม่มีเสียง
**แก้:** สร้าง `AudioContext` ครั้งเดียวตอนกด "เริ่ม" (ซึ่งนับเป็น user gesture) แล้วใช้ซ้ำ

### 8. ตารางล้นจอมือถือ (กลาง)
ตารางประวัติคาร์ดิโอมี 7 คอลัมน์ (`index.html:1178`) บนจอ 360px จะดันหน้าจนเลื่อนซ้าย-ขวาได้ทั้งหน้า
**แก้:** ครอบตารางด้วย `<div style="overflow-x:auto">` หรือเปลี่ยนเป็นการ์ดบนมือถือ

### 9. กราฟกล้ามเนื้อตอนไม่มีข้อมูล (ต่ำ)
`index.html:931` เขียนพิกัด `clearRect(0,0,400,200)` และ `fillText(...,200,100)` ไว้ตายตัว แต่ canvas เป็น responsive ข้อความจึงไม่อยู่กลางและอาจลบไม่หมด
**แก้:** ใช้ `canvas.width/height` จริง หรือซ่อน canvas แล้วแสดง `.empty-state` แทน

### 10. Quick log modal ไม่ล้างค่า (ต่ำ)
`saveQuickLog` (`index.html:1444`) ไม่เคลียร์ช่อง duration/cals/note พอเปิด modal ครั้งถัดไปจะเห็นค่าเก่าค้างอยู่ และ modal ยังปิดด้วยปุ่ม Esc หรือคลิกพื้นหลังไม่ได้

### 11. Service worker (ต่ำ)
- `CACHE = 'fittrack-v1'` ไม่เคยเปลี่ยน เพราะใช้แบบ stale-while-revalidate ผู้ใช้จะเห็นเวอร์ชันใหม่ช้าไป 1 รอบการเปิดเสมอ และไม่มีอะไรแจ้งว่ามีอัปเดต
- SW cache ทุก GET รวมถึง cross-origin ที่เป็น opaque ทำให้ cache โตขึ้นเรื่อย ๆ

**แก้:** bump ชื่อ cache ทุกครั้งที่ deploy แสดงแถบ "มีเวอร์ชันใหม่ กดรีโหลด" และจำกัดว่าให้ cache เฉพาะ origin ตัวเองกับ CDN ที่ใช้

### 12. Manifest (ต่ำ)
`"purpose": "any maskable"` ที่รวมไว้ในค่าเดียว ไม่ได้รับการแนะนำแล้ว เพราะไอคอนแบบ any จะถูก crop ผิด ควรแยกเป็นไอคอน `any` กับ `maskable` คนละไฟล์ (ไฟล์ maskable ต้องมี safe zone)

### 13. นาฬิกาพักตอนล็อกจอ (ข้อจำกัด)
ตอนล็อกจอหรือสลับแอปบนมือถือ JS จะหยุดทำงาน ทำให้การแจ้งเตือนอาจไม่เด้งจนกว่าจะกลับมาเปิดแอป เรื่องนี้แก้ใน PWA ได้ยาก แต่ควรบอกผู้ใช้ หรือใช้ Wake Lock API (`navigator.wakeLock`) กันจอดับระหว่างพัก

### 14. Accessibility (ต่ำ)
- `<label>` ไม่ได้ผูกกับ input ด้วย `for`/`id` ทำให้ screen reader อ่านไม่ออกว่าช่องไหนคืออะไร
- ปุ่ม `✕` ไม่มี `aria-label`
- modal ไม่มี `role="dialog"` และไม่มี focus trap
- nav ไม่มี `aria-current`

## โครงสร้างโค้ด (ระยะยาว)

ตอนนี้ HTML, CSS และ JS อยู่ในไฟล์เดียว แอปขนาดนี้ยังรับได้ แต่ถ้าเพิ่มฟีเจอร์ตามรายการข้างบนจะดูแลยากขึ้น:

- แยกเป็น `styles.css`, `app.js`, `data.js` (EXERCISES, PLAN, PROGRAMS) และ `storage.js`
- เปลี่ยน inline `onclick="..."` เป็น `addEventListener` หรือ event delegation
- ใส่ `schemaVersion` ใน state ไว้ทำ migration ตอนเปลี่ยนโครงสร้างข้อมูล
- อาจใช้ ES modules (`<script type="module">`) ได้โดยไม่ต้องมี build tool
- `EXERCISES` ใน `index.html:776` เป็นข้อมูลล้วน ควรแยกออกไปเป็นไฟล์ของตัวเอง

## สิ่งที่ทำได้ดีแล้ว (ควรเก็บไว้)

- `esc()` ใช้ escape note ของผู้ใช้ทุกจุดที่แสดงผล
- `todayStr()` ใช้เวลาท้องถิ่นแทน `toISOString()`
- นาฬิกาพักและ stopwatch อิง timestamp จริง ไม่ใช่การนับ tick
- การแจ้งเตือนส่งผ่าน `serviceWorker.showNotification` ซึ่งใช้ได้บน Android PWA
- เกณฑ์ BMI ใช้ค่าของคนเอเชีย (23 / 25) ซึ่งเหมาะกับผู้ใช้ไทย
- โซนหัวใจใช้สูตร Karvonen ที่คิดจาก HR พักด้วย ไม่ได้ใช้แค่ %MHR
- ทำลาย Chart instance ก่อนวาดใหม่ทุกครั้ง จึงไม่มี memory leak จากกราฟ
