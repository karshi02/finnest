# รายงาน #18: นาฬิกาหลุดบ่อย และรีเฟรชแล้วไม่จำ

วันที่: 2026-10-08
Deploy: https://fitt-zeta.vercel.app (cache `fittrack-v8`)

## ผลจากการลองจริงของผู้ใช้

> มันชอบหลุด และรีเว็บมันจะไม่จำ และหลุดเหมือนกัน

แปลว่า **HUAWEI WATCH GT 6 เชื่อมต่อได้แล้ว** เหลือปัญหาความเสถียร 2 ข้อ

## สาเหตุ

| อาการ | สาเหตุ |
|---|---|
| หลุดบ่อย | เดิมลองเชื่อมใหม่แค่ 3 ครั้งภายในไม่กี่วินาทีแล้วเลิก ถ้านาฬิกาพักจอหรือสัญญาณหายนานกว่านั้นก็หลุดถาวร และ event หลุดที่ซ้ำกันทำให้เริ่มเชื่อมใหม่ 2 รอบชนกัน |
| รีเฟรชแล้วหลุด/ไม่จำ | เบราว์เซอร์ตัด Bluetooth ทุกครั้งที่รีเฟรชหน้า และ Chrome ส่วนใหญ่ยังไม่เปิด `getDevices()` ให้ใช้ (ยังต้องเปิด flag) จึงต้องให้ผู้ใช้กดเลือกใหม่ เว็บเลี่ยงข้อนี้ไม่ได้ |

## สิ่งที่แก้ (`index.html`, `sw.js`)

| เรื่อง | รายละเอียด |
|---|---|
| เชื่อมใหม่อัตโนมัติ | รอ 1, 2, 4, 8, 10, 10... วินาที สูงสุด 30 ครั้ง (ประมาณ 5 นาที) กันการเชื่อมซ้อนเมื่อ event หลุดมาซ้ำ |
| ค่าหยุดมา | เชื่อมอยู่แต่ไม่มีค่าเกิน 20 วินาที (เช่น นาฬิกาพักจอ) จะตัดแล้วเชื่อมใหม่เอง |
| ค่าเฉลี่ยไม่หาย | HR เฉลี่ย/สูงสุดของรอบ stopwatch ยังอยู่หลังเชื่อมใหม่ |
| จอไม่ดับ | ขอ Wake Lock ระหว่างเชื่อมนาฬิกา (มือถือที่จอดับมักตัด Bluetooth) |
| จำนาฬิกา | เก็บชื่อและ id ของนาฬิกาล่าสุด ถ้าเบราว์เซอร์มี `getDevices()` จะเชื่อมให้เองหลังรีเฟรช ถ้าไม่มี จะขึ้น "ครั้งก่อนใช้ HUAWEI WATCH GT 6-55C — กดเชื่อมต่อเพื่อเชื่อมอีกครั้ง" |
| เตือนก่อนรีเฟรช | ถ้ากำลังเชื่อมนาฬิกาอยู่ เบราว์เซอร์จะถามก่อนรีเฟรชหรือปิดหน้า |
| ข้อความผิดพลาด | ข้อความ "นาฬิกาไม่ตอบ" ไม่ถูก event หลุดเขียนทับเป็น "ตัดการเชื่อมต่อแล้ว" อีก |

## การทดสอบ

Web Bluetooth จำลองที่ยิง event หลุดเหมือนของจริง:

| ทดสอบ | ผล |
|---|---|
| เชื่อมแล้วจำชื่อนาฬิกา | ✅ |
| หลุด (event มาซ้ำ 2 ครั้ง) แล้วเชื่อมใหม่เองแค่ 1 รอบ และค่าเฉลี่ยยังอยู่ | ✅ ✅ ✅ ✅ |
| ค่าหยุดมา 20 วินาที แล้วเชื่อมใหม่เอง | ✅ |
| นาฬิกาไม่ตอบหลายรอบ: ยังพยายามต่อเกิน 3 ครั้ง และกลับมาได้เมื่อนาฬิกาตอบ | ✅ ✅ |
| เตือนก่อนรีเฟรชเมื่อเชื่อมอยู่ และไม่เตือนเมื่อไม่ได้เชื่อม | ✅ ✅ |
| กดตัดเองแล้วไม่เชื่อมใหม่ | ✅ |
| ข้อความเชื่อมไม่สำเร็จไม่ถูกเขียนทับ | ✅ |
| รีเฟรช: แสดงชื่อนาฬิกาเดิม / เชื่อมเองเมื่อมี `getDevices()` | ✅ ✅ |

รวมชุดเดิมทั้งหมด **66/66 ผ่าน** (Bluetooth 47 + Strava 19)

## ข้อจำกัดที่เหลือ

- Chrome ทั่วไปยังให้เว็บเชื่อม Bluetooth เองหลังรีเฟรชไม่ได้ ต้องกดปุ่ม 1 ครั้งและเลือกนาฬิกา (เปิดให้เชื่อมเองได้ที่ `chrome://flags/#enable-web-bluetooth-new-permissions-backend` แต่เป็นฟีเจอร์ทดลอง)
- ถ้าหน้า HR Data Broadcasts บนนาฬิกาปิดไป (เช่น กดออก) นาฬิกาจะหยุดส่ง แอปจะพยายามเชื่อมใหม่ประมาณ 5 นาที
- บนมือถือ ถ้าสลับไปแอปอื่นนาน ๆ Chrome อาจหยุดหน้าเว็บและทำให้หลุด
