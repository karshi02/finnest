# แผน: ซิงก์กิจกรรมจากสมาร์ทวอทช์ผ่าน Strava

วันที่: 2026-10-05
สถานะ: **ร่างแผน ยังไม่ได้ลงมือ**
ต่อจาก: [FIX-REPORT-04.md](FIX-REPORT-04.md) (HR สดผ่าน Bluetooth เสร็จแล้ว)

---

## 1. เป้าหมาย

กิจกรรมคาร์ดิโอที่บันทึกบนนาฬิกา (วิ่ง, ปั่น, ว่ายน้ำ, เดิน ฯลฯ) เข้ามาอยู่ในประวัติคาร์ดิโอของ FitTrack เองโดยไม่ต้องพิมพ์ ข้อมูลที่ได้: วันที่, เวลา, ระยะทาง, HR เฉลี่ย/สูงสุด และแคลอรี่

**ไม่อยู่ในขอบเขต:**
- ส่งข้อมูลจาก FitTrack กลับไป Strava
- ท่า/น้ำหนัก/reps ของเวทเทรนนิ่ง เพราะ Strava ไม่มีข้อมูลนี้
- ข้อมูลการนอนหรือจำนวนก้าว

## 2. ทำไมต้องผ่าน Strava

- แอปเป็น PWA จึงอ่าน Health Connect ของ Android ไม่ได้
- นาฬิกาเกือบทุกยี่ห้อซิงก์เข้า Strava ได้อยู่แล้ว (Garmin, Coros, Polar, Amazfit/Zepp, Huawei, Samsung Health, Wear OS ผ่านแอปเสริม) ต่อกับ Strava ที่เดียวจึงครอบคลุมทุกยี่ห้อ
- Strava API ใช้ OAuth บนเว็บได้ และแอปใหม่อยู่ในโหมดใช้ได้คนเดียว (เจ้าของแอป) ซึ่งพอดีกับการใช้ส่วนตัว

## 3. สถาปัตยกรรม

```
 นาฬิกา ──sync──> Strava
                     ▲   │
          OAuth/API  │   │ activities (JSON)
                     │   ▼
 FitTrack (PWA, เบราว์เซอร์) ──แลก/ต่ออายุ token──> Cloudflare Worker (เก็บ Client Secret)
```

- **Worker** มีหน้าที่เดียว: เอา `code` หรือ `refresh_token` ไปแลก token กับ Strava โดยใช้ Client Secret ที่ซ่อนไว้ใน Worker เพราะห้ามใส่ secret ไว้ในหน้าเว็บ
- **การดึงกิจกรรม** เบราว์เซอร์เรียก Strava API เองโดยตรงด้วย access token Worker จึงเล็กและเกือบไม่มี state
- **ที่เก็บ token** เก็บใน localStorage key แยก `fittrack-strava` **ไม่ใส่ใน state หลัก และไม่ติดไปกับไฟล์ Export**

| Strava | FitTrack |
|---|---|
| Run, TrailRun, VirtualRun | วิ่ง |

## 9. ความปลอดภัย

- Client Secret อยู่ใน Worker เท่านั้น (ใช้ `wrangler secret`) ไม่อยู่ใน git และไม่อยู่ในหน้าเว็บ
- Worker ตอบเฉพาะ request ที่มี `Origin` เป็นโดเมนแอป (CORS allowlist)
- OAuth ใช้พารามิเตอร์ `state` แบบสุ่มเพื่อกัน CSRF
- ขอ scope แค่อ่าน (`activity:read_all`) ไม่ขอสิทธิ์เขียน
- token อยู่ใน localStorage ถ้าแอปมีช่องโหว่ XSS ก็อาจถูกขโมยได้ ความเสี่ยงนี้ลดลงแล้วเพราะ escape ครบตั้งแต่รายงาน #1 ถ้าต้องการปลอดภัยกว่านี้ ทางเลือกคือเก็บ refresh token ไว้ฝั่ง Worker (KV) แล้วให้แอปถือแค่ session id แต่งานจะเพิ่มขึ้นราว 3–4 ชม.
- ปุ่มยกเลิกการเชื่อมต่อต้องเพิกถอนสิทธิ์ที่ Strava ด้วย (`/oauth/deauthorize`) ไม่ใช่แค่ลบ token ในเครื่อง

## 10. ความเสี่ยงและข้อจำกัด

| ความเสี่ยง | ผลกระทบ | การรับมือ |
|---|---|---|
| Strava เปลี่ยนเงื่อนไขหรือ rate limit ของ API | ซิงก์ช้าลงหรือใช้ไม่ได้ | ใช้คนเดียวเรียก API น้อยมาก และจำกัดการเรียกต่อรอบไว้แล้ว (S5) |
| แคลอรี่ต้องเรียก API ทีละกิจกรรม | ซิงก์ครั้งแรกที่มีย้อนหลังเยอะจะได้แคลอรี่ไม่ครบในรอบเดียว | ทยอยดึงรอบละไม่เกิน 20 รายการ |
| นาฬิกาบางยี่ห้อส่งเข้า Strava ไม่ตรง เช่น ไม่มี HR | ฟิลด์ว่าง | แสดง "-" ตามเดิม |
| แอป Strava อยู่ในโหมดใช้ได้คนเดียว | คนอื่นเชื่อมต่อไม่ได้ | ถ้าจะเปิดให้คนอื่นใช้ ต้องขอ Strava เพิ่มจำนวนผู้ใช้ และต้องเปลี่ยนไปเก็บ token ฝั่ง server |
| Worker ล่ม หรือโควตาฟรีหมด | เชื่อมต่อหรือ refresh ไม่ได้ แต่ข้อมูลเดิมยังอยู่ | free tier เกินพอสำหรับใช้คนเดียว |

## 11. ทางเลือกอื่น (ถ้าไม่ใช้ Strava)

- **นำเข้าไฟล์ `.fit` / `.gpx` / `.tcx`:** ไม่ต้องมี server แต่ต้องกด export จากแอปนาฬิกาแล้วนำเข้าเองทุกครั้ง (ประมาณ 4–6 ชม.)
- **ห่อเป็นแอป Android จริง (Capacitor) + Health Connect:** ได้ข้อมูลครบที่สุด รวมการนอนและก้าวเดิน แต่ต้องดูแลแอปบน Play Store เป็นงานใหญ่ (มากกว่า 20 ชม.)

## 12. ก่อนเริ่มลงมือต้องได้คำตอบเหล่านี้

1. ยี่ห้อ/รุ่นนาฬิกา และนาฬิกาซิงก์เข้า Strava อยู่แล้วหรือยัง
2. ตอบเรื่องที่ต้องตัดสินใจในข้อ 5 (หรือใช้ค่าที่แนะนำ)
3. Deploy FitTrack ขึ้น https แล้วหรือยัง และใช้โดเมนอะไร
