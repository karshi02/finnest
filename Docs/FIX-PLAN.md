## 1. Workflow ต่องาน

ทุกงานในตารางด้านล่างทำตามขั้นตอนเดียวกัน:

```
1. git switch -c fix/<task-id>-<ชื่อสั้น>        เช่น fix/1.1-safe-load
2. แก้โค้ดตาม FIX-GUIDE.md
3. รันในเครื่อง  →  ทดสอบตามคอลัมน์ "ทดสอบ" ของงานนั้น
4. ทดสอบซ้ำ (regression) แบบเร็ว: เปิดทุกหน้า, บันทึก 1 set, บันทึกคาร์ดิโอ 1 รายการ, ดู Console ว่าไม่มี error
5. git commit  (1 งาน = 1 commit, ข้อความเช่น "fix: safe state loading with corrupt backup")
6. merge เข้า main
```

**ต่อรอบ (release):**

```
1. bump CACHE ใน sw.js  (fittrack-v2, v3, ...)
2. รัน checklist ทดสอบของรอบนั้นครบทุกข้อ
3. git tag v1.<รอบ>  →  push  →  deploy
4. ทดสอบบนมือถือจริง (Android Chrome + iOS Safari ถ้ามี) ว่าได้เวอร์ชันใหม่
5. ใช้เองจริง 2–3 วันก่อนเริ่มรอบถัดไป
```

**ถ้า deploy แล้วมีปัญหา (rollback):** `git revert` commit ที่มีปัญหา → bump `CACHE` อีกครั้ง → deploy ใหม่
ถ้าข้อมูลผู้ใช้เสียไปแล้ว ให้ Import จากไฟล์ backup (ซึ่งจะใช้ได้ตั้งแต่รอบ 1)

## 2. แผนงาน

ความยาก: S = ไม่ถึง 1 ชม., M = 1–3 ชม., L = มากกว่า 3 ชม.

### รอบ 1: กันข้อมูลหาย → release `v1.1`

| ID | งาน | ขึ้นกับ | ความยาก | ทดสอบ |
|---|---|---|---|---|
| 1.1 | `loadState()` + `save()` ที่มี try/catch | ไม่มี | S | ใส่ `{bad` ใน localStorage แล้วแอปยังเปิดได้ และมี key `fittrack-corrupt-*` |
| 1.2a | **ครอบ `esc()` ให้ครบทุกฟิลด์** | ไม่มี | S | import ไฟล์ที่มี `<img onerror>` แล้วไม่มี alert เด้ง |
| 1.2b | Export / Import | 1.1, **1.2a** | M | export → ล้างข้อมูล → import แล้วข้อมูลกลับมาครบ |
| 1.3 | Vendor Chart.js + guard `typeof Chart` | ไม่มี | S | ตัดเน็ตหลังติดตั้งแอป กราฟยังแสดงได้ |

> **ห้าม** release 1.2b โดยไม่มี 1.2a เพราะ Import จะเปิดช่องให้ไฟล์จากภายนอกฝังสคริปต์ (XSS) เข้าแอปได้

**เกณฑ์รอบเสร็จ:** export ข้อมูลจริงของตัวเองได้ และ import กลับในเบราว์เซอร์อื่นได้ครบ

### รอบ 2: ความถูกต้องของข้อมูล → release `v1.2`

| ID | งาน | ขึ้นกับ | ความยาก | ทดสอบ |
|---|---|---|---|---|
| 2.1 | helper `num()` + validate ทุกฟอร์ม | ไม่มี | M | reps -5, sets 9999, 1RM reps 40 ถูกปฏิเสธทั้งหมด |
| 2.2 | `localDateStr` / `parseLocalDate` + migration วันที่ | 1.1 | M | โหลด `test-data.json` แล้ววันที่ทุกแถวถูกต้อง เปลี่ยน timezone เครื่องเป็น US แล้ววันไม่เลื่อน |
| 2.3 | set ค้างข้ามวัน | 2.2 | S | เปลี่ยนเวลาเครื่องเป็นวันถัดไป แล้ว session ลงวันเดิม และมีคำเตือน |
| 2.4 | กราฟ 7 วันล่าสุด | 2.2 | S | รายการที่ลงวันในอนาคตไม่เข้ากราฟ และลำดับวันในกราฟถูก |
| 2.5 | `id` + ลบประวัติ | 1.1 | M | ลบรายการกลางลิสต์แล้วรายการที่ถูกลบตรงกับที่กด |
| 2.6 | `.table-wrap` | ไม่มี | S | จอ 360px ไม่มี scroll แนวนอนทั้งหน้า |

ลำดับที่แนะนำ: 2.6 → 2.1 → 2.2 → 2.3 → 2.4 → 2.5 (เริ่มจากงานที่ไม่แตะข้อมูลก่อน)

**ก่อน release:** export ข้อมูลจริงของตัวเองเก็บไว้ แล้วทดสอบ migration กับสำเนาของข้อมูลจริงในเบราว์เซอร์แยก (เช่น profile ใหม่) ก่อน deploy

**เกณฑ์รอบเสร็จ:** ข้อมูลจริงผ่าน migration แล้วไม่มีรายการหายหรือวันที่เพี้ยน ตรวจโดยนับจำนวน session และ cardio ก่อนและหลัง migration ให้เท่ากัน

## 5. หลังรอบ 4: ฟีเจอร์ใหม่

ทำหลังโค้ดแยกไฟล์แล้ว จะเพิ่มฟีเจอร์ได้ง่ายกว่า เรียงตามคุ้มค่า:

4. บันทึกน้ำหนักตัว / สัดส่วน (M)
5. แผนแก้ไขได้ + เริ่ม workout จากแผน (L)
6. ซิงก์ข้ามเครื่อง (L): ต้องออกแบบ auth และ backend แยก ควรมีเอกสารออกแบบของตัวเองก่อนเริ่ม
