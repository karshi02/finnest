# รายงาน #27: หน้าการแข่งขัน — แข่งจบแล้วยังขึ้นว่ากำลังแข่ง

วันที่: 2026-10-16
Deploy: https://fitt-zeta.vercel.app (cache `fittrack-v14`)

## อาการที่แจ้ง

"บางทีหน้าส่วนการแข่งขันบั๊ก แข่งจบแล้วยังขึ้นอยู่"

## สาเหตุที่พบ (สแกนทั้ง server และหน้าเว็บ)

| # | บั๊ก | ผล |
|---|---|---|
| 1 | หน้าแข่งขันโหลดข้อมูลครั้งเดียวตอนเปิดหน้า ไม่รู้ตัวเมื่อถึงเวลาจบ | ยังขึ้น "กำลังแข่ง · หมดเวลา" และมีปุ่ม "ไปทำชาเลนจ์" ค้างจนกว่าจะรีเฟรช |
| 2 | ดวลยาว 24 ชม. เต็มเสมอ แม้ทั้งสองฝ่ายทำเสร็จแล้ว | ทำเสร็จแล้วแต่ยังขึ้นว่ากำลังแข่ง ในฐานข้อมูลจริงมีดวลของผู้ใช้ค้างแบบนี้ 4 รายการ |
| 3 | รายการที่จบแล้วปนกับรายการที่กำลังแข่ง เรียงสลับกัน | ที่จบแล้วบางทีขึ้นอยู่บนสุด |
| 4 | ใช้นาฬิกาของเครื่องผู้ใช้คิดเวลาที่เหลือ | ถ้านาฬิกาเครื่องเพี้ยน สถานะก็เพี้ยนตาม |
| 5 | token ใช้ไม่ได้ แต่ server ตอบเหมือนผู้ใช้ไม่ได้เข้าสู่ระบบ (ไม่ส่ง error) | ดวลและทีมของผู้ใช้ "หายไป" เฉย ๆ เป็นบางครั้ง |
| 6 | คำท้าที่ไม่มีคนรับจนหมดอายุ | ขึ้น "จบแล้ว" คู่กับ "รอคนรับคำท้า" และไม่มีปุ่มยกเลิก คำท้าจึงค้างสะสม |
| 7 | แข่งทีม: เวลาเริ่มใช้นาฬิกาฐานข้อมูล แต่ตอนเช็กใช้นาฬิกา server | สร้างแล้วส่งผลทันที ผลไม่ถูกนับเข้าการแข่ง (เทสจับได้) |

## สิ่งที่แก้

- **สถานะตามเวลาจริง** (เกี่ยวกับบั๊ก #1)
  - ถึงเวลาจบ หน้าจอเปลี่ยนเป็น "หมดเวลา · กำลังสรุปผล" ทันที และปุ่มไปทำชาเลนจ์หายไป
  - จากนั้นดึงผลสุดท้ายจาก server เอง แล้วแสดงผู้ชนะ
  - เวลาที่เหลืออัปเดตทุกนาที และโหลดใหม่เมื่อกลับมาเปิดแท็บ
- **ดวลจบทันทีเมื่อทั้งสองฝ่ายมีผลที่ผ่านการตรวจ** (บั๊ก #2) ประกาศผลและให้เหรียญเลย ถ้ามีผลฝ่ายเดียวหรือไม่มีใครทำ ยังปิดเองเมื่อครบ 24 ชม.
- **แยกรายการ** (บั๊ก #3) ที่กำลังแข่งอยู่ด้านบน เรียงตามที่ใกล้จบก่อน ส่วนที่จบแล้วพับไว้ในหัวข้อ "🏁 การแข่งที่จบแล้ว"
- **ใช้เวลาของ server** (บั๊ก #4) server ส่ง `server_time` มาด้วย หน้าเว็บนำไปปรับเวลา
- **token เสีย** (บั๊ก #5) server ตอบ 401 หน้าเว็บจึงต่ออายุ token เอง ถ้าต่ออายุไม่ได้ จะออกจากระบบแล้วแสดงข้อมูลสาธารณะแทนการขึ้น error
- **คำท้า** (บั๊ก #6) คำท้าที่หมดอายุขึ้นว่า "คำท้าหมดอายุ" ผู้สร้างกด **ยกเลิกคำท้า** ได้ (action ใหม่ `duel_cancel`) และรหัสท้าบอกเวลาหมดอายุ
- **เวลาเริ่มแข่งทีม** (บั๊ก #7) server เป็นคนกำหนดเวลาเริ่มเอง

## การทดสอบ

**เทสใหม่ `run13.js`:** รันกับ Chrome แบบเวลาจริง 13/13 ผ่านติดกัน 3 รอบ ครอบคลุม:
- การแข่งจบระหว่างที่เปิดหน้าค้างไว้
- ระหว่างที่ server ยังไม่ปิด
- หลัง server ปิดแล้วแสดงผู้ชนะ
- นาฬิกาเครื่องช้ากว่า server 1 ชม.
- token เสีย
- คำท้าหมดอายุ
- การแข่งที่ยังไม่เริ่ม
- การเรียงลำดับ

**ตรวจกับฐานข้อมูลจริง:** เพิ่มเป็น 70 ข้อ ผ่านหมด เพิ่มกรณีต่อไปนี้:
- ยกเลิกคำท้า
- คนอื่นยกเลิกคำท้าของเราไม่ได้
- คำท้าที่ยกเลิกแล้วรับไม่ได้
- ดวลจบทันทีเมื่อทั้งคู่ส่งผล และผู้ชนะได้เหรียญเลย
- ดวลที่ไม่มีผลปิดเองเมื่อหมดเวลา
- token เสียได้ 401

**ชุดเดิมทั้งหมด:** ผ่าน ได้แก่ หน้าจอ 40, unit 32, กล้อง 8, แอปหลัก 136

**บนเว็บจริงหลัง deploy:** ส่ง token เสียแล้วได้ 401, มี `server_time` ใน response และหน้าเว็บเป็นโค้ดใหม่แล้ว

## สถานะดวลจริงในฐานข้อมูลตอนนี้

| ดวล | สถานะ | หมายเหตุ |
|---|---|---|
| 13, 15, 24 | กำลังแข่ง | ส่งผลแล้วแค่ฝ่ายเดียว |
| 26 | กำลังแข่ง | ยังไม่มีใครส่งผล |
| 14, 25 | รอคนรับ | |

ดวลที่กำลังแข่ง 4 รายการจะจบเองเมื่อคู่แข่งส่งผล หรือเมื่อครบ 24 ชม. ส่วนคำท้า 14 และ 25 ผู้สร้างกดยกเลิกเองได้แล้ว

## เรื่องเล็กที่เจอระหว่างทาง

เทสกับฐานข้อมูลจริงเคยตกเป็นบางครั้ง เพราะชนลิมิตสมัครสมาชิก 5 ครั้งต่อ IP ต่อวันของระบบเอง ซึ่งแปลว่าลิมิตทำงานถูกต้อง แก้ให้เทสใช้ IP สุ่มในแต่ละรอบแล้ว
