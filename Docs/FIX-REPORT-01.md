## สิ่งที่แก้ (ตาม ID ในแผน)

### รอบ 1: กันข้อมูลหาย

**1.1 โหลดข้อมูลอย่างปลอดภัย**
- เพิ่ม `loadState()` ที่ครอบ `JSON.parse` ด้วย try/catch ถ้าข้อมูลเสีย จะสำรองข้อมูลดิบไว้ที่ `fittrack-corrupt-<เวลา>` แจ้งผู้ใช้ แล้วเริ่มใหม่
- เพิ่ม `normalizeState()` ที่กรองข้อมูลแปลก ๆ ออก เช่น record ที่ไม่ใช่ object, `sets` หรือ `muscles` ที่ไม่ใช่ array และ `volume` ที่ไม่ใช่ตัวเลข
- `save()` ครอบ try/catch แล้ว ถ้าพื้นที่เต็มจะแจ้งให้ผู้ใช้ export

**1.2a Escape ทุกฟิลด์ (กัน XSS)**
- ทุกค่าที่มาจากข้อมูลผู้ใช้ผ่าน `esc()` หมดแล้ว ได้แก่ ชื่อท่า, ประเภทคาร์ดิโอ, ระดับ, ตัวเลขทุกตัว, วันที่ และชื่อกล้ามเนื้อ
- ทำ helper ใหม่ `muscleBadge()` และ `muscleColor()` ใช้แทน badge ที่เคยก๊อปซ้ำ 4 ที่ สีใน `style` จะมาจาก map ที่เขียนไว้ในโค้ดเท่านั้น
- ปุ่มลบส่ง id ผ่าน `data-id` + `this.dataset.id` แทนการแปะ id ลงใน `onclick` ตรง ๆ เพราะวิธีเดิมเปิดช่องให้ id ที่มีเครื่องหมาย `'` ฝังโค้ดได้

**1.2b Export / Import**
- เพิ่มปุ่ม `⬇ Export` และ `⬆ Import` ที่หน้าภาพรวม
- Export ได้ไฟล์ `fittrack-backup-YYYY-MM-DD.json` ที่มี `version` กำกับ
- Import ตรวจโครงสร้างไฟล์ก่อน และถามยืนยันพร้อมบอกจำนวนรายการก่อนเขียนทับ จากนั้นข้อมูลผ่าน `normalizeState` + `migrate` เสมอ

**1.3 Chart.js**
- ดาวน์โหลด Chart.js **4.4.4** มาไว้ที่ `vendor/chart.umd.min.js` และใส่ไว้ใน SW cache แล้ว จึงทำงานออฟไลน์ได้ตั้งแต่ครั้งแรกที่ติดตั้ง และไม่โดน major version ใหม่เปลี่ยนเองอีก
- ฟังก์ชันวาดกราฟทุกตัวเช็ก `typeof Chart` ก่อน ถ้าโหลดไม่ได้ หน้าที่เหลือยังใช้งานได้

### รอบ 2: ความถูกต้อง

**2.1 Validate input**
- เพิ่ม helper `num(id, {min, max, int})` และ `optNum()` (ใช้กับช่องที่ไม่บังคับกรอก)
- ช่วงค่าที่รับ:

| ฟอร์ม | ช่วงค่า |
|---|---|
| Set | น้ำหนัก 0–1000, reps 1–100, sets 1–20, RIR 0–10 |
| คาร์ดิโอ / บันทึกด่วน | เวลา 1–1440 นาที, ระยะ 0–1000 km, HR 30–230, kcal 0–20000 |
| BMR / BMI | อายุ 10–100, น้ำหนัก 30–300, ส่วนสูง 100–250 |
| Macro | kcal 1000–6000, น้ำหนักตัว 30–300 |
| 1RM | น้ำหนัก 1–1000, reps 1–30 |
| โซนหัวใจ | อายุ 10–90, HR พัก 30–100 |

- 1RM: ถ้า reps เกิน 10 จะใช้แค่สูตร Epley พร้อมคำเตือนว่าคลาดเคลื่อนสูง และไม่มีโอกาสได้ Infinity อีก

**2.2 รวมวันที่ให้เป็นรูปแบบเดียว + migration**
- เพิ่ม `localDateStr()`, `parseLocalDate()` และ `fmtDate()` แล้วเปลี่ยน `new Date(x.date)` ทุกจุดมาใช้ตัวใหม่
- ข้อมูลเดิม (schema v1) จะถูก migrate อัตโนมัติ: วันที่แบบ ISO เต็มเปลี่ยนเป็น `YYYY-MM-DD` ตามเวลาท้องถิ่น (เวลาเดิมเก็บไว้ใน `ts`) และใส่ `id` ให้ทุก record
- **ก่อน migrate ครั้งแรก ระบบจะสำรองข้อมูลเดิมไว้ที่ `fittrack-backup-v1` ให้อัตโนมัติ**
- ใส่ `schemaVersion: 2` ไว้ใน state สำหรับ migration ครั้งต่อไป

**2.3 Set ค้างข้ามวัน**
- `saveSession` ใช้วันที่ของ set แรก ไม่ใช่วันที่ตอนกดบันทึก
- ถ้าพบ set ที่ค้างจากวันก่อน จะมีกล่องเตือนสีส้มเหนือรายการ set

**2.4 กราฟ "7 วันล่าสุด"**
- คำนวณตามวันที่จริงย้อนหลัง 7 วัน โดยวันนี้อยู่ขวาสุด รายการที่ลงวันในอนาคตไม่ถูกนับ
- เปลี่ยนหัวข้อการ์ดจาก "ความก้าวหน้าสัปดาห์นี้" เป็น "7 วันล่าสุด"

**2.5 ลบประวัติ**
- มีปุ่ม ✕ ในประวัติเวทเทรนนิ่งและประวัติคาร์ดิโอ ลบผ่าน `id` และถามยืนยันก่อน
- รายการประวัติเรียงใหม่สุดก่อนตามวันที่จริง (เดิมเรียงตามลำดับที่บันทึก ถ้าบันทึกย้อนหลังลำดับจะผิด)
- **ยังแก้ไขรายการไม่ได้** ดู "ยังไม่ได้ทำ"

**2.6 ตารางล้นจอมือถือ**
- ตารางทั้ง 4 จุด (บันทึกล่าสุด, ประวัติคาร์ดิโอ, โซนหัวใจ, 1RM) ถูกครอบด้วย `.table-wrap` ที่เลื่อนแนวนอนได้ในตัว

### รอบ 3: UX

| ID | สิ่งที่ทำ |
|---|---|
| 3.1 | ใช้ `AudioContext` ตัวเดียว สร้างตอนกด "เริ่ม" (นับเป็น user gesture) มือถือจึงไม่ปิดเสียงตอนหมดเวลา และไม่มี context ค้างสะสม |

### นอกแผน

- **หน้าล้นจอมือถือ 6px (บั๊กเดิม):** ที่ 360px การ์ดกราฟใน `.grid2` ไม่ยอมหดเพราะ canvas จึงดันหน้ากว้างเป็น 366px ทดสอบแล้วโค้ดต้นฉบับก็เป็นแบบนี้ แก้ด้วย `min-width: 0` ให้ช่อง grid และลด padding ของ `main` บนมือถือเหลือ 16px
- **Macro:** ถ้าแคลอรี่ต่ำจนโปรตีนกับไขมันรวมกันเกิน จะแสดงคำเตือนแทนการตัดคาร์บเป็น 0 เงียบ ๆ และถ้าไม่ได้กรอกน้ำหนักตัว จะบอกว่าใช้ค่า 70 kg

## สิ่งที่ต้องทำต่อ (ฝั่งคุณ)

1. **ก่อน deploy: export ข้อมูลจริงเก็บไว้** ตอนนี้แอปเวอร์ชันเดิมบนมือถือยังไม่มีปุ่ม Export ให้ใช้วิธีในแผนข้อ 0.1 แทน (DevTools → `copy(localStorage.getItem('fittrack'))`) ถึงระบบจะสำรองไว้ที่ `fittrack-backup-v1` ให้อัตโนมัติแล้ว แต่สำเนานั้นอยู่ในเบราว์เซอร์เดียวกัน ถ้าเบราว์เซอร์ล้างข้อมูลก็หายไปพร้อมกัน
2. ตรวจ diff: `git diff main -- index.html sw.js manifest.json`
3. Commit: ตอนนี้ยังไม่ได้ commit ถ้าต้องการ ผม commit แยกตามรอบให้ได้
4. Merge เข้า `main`, push แล้ว deploy
5. ทดสอบบนมือถือจริงตามรายการ "ยังไม่ได้ทดสอบ" ข้างบน แล้วใช้จริง 2–3 วัน

ทุกครั้งที่ deploy เวอร์ชันถัดไป ต้องเปลี่ยน `CACHE` ใน `sw.js` เป็น `fittrack-v3`, `v4`, ... ไม่เช่นนั้นผู้ใช้จะได้ไฟล์เก่าจากแคช
