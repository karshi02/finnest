# แผนปรับ UI ครั้งใหญ่: FitTrack Pro

วันที่ 2026-10-17 · สถานะ: **ทำแล้ว ดู [FIX-REPORT-20.md](FIX-REPORT-20.md)** · ตรวจด้วย impeccable (critique + audit, ผู้ตรวจ 2 ทางแยกกัน)

## 1. สรุปสั้น

- คะแนน Nielsen **20/40** (ใช้งานได้ แต่ติดขัดทุกขั้น)
- ตรวจอัตโนมัติเจอ **45 จุด** เรื่องคอนทราสต์ (มาจากสาเหตุจริงประมาณ 6 ข้อ)
- คำตัดสินดีไซน์: **ดูเป็นเทมเพลตฟิตเนสทั่วไป** ได้แก่ พื้นดำ, header ไล่สีแดงไปฟ้า, การ์ดมุมโค้ง 16px เท่ากันทุกใบ, emoji แทนไอคอน, ตัวเลข 4 สีที่สีไม่มีความหมาย และฟอนต์ Segoe UI ที่ไม่มีฟอนต์ไทย
- จุดเด่นที่ไม่มีแอปไหนมี ได้แก่ **กล้องนับท่า** และ **ดวล/ทีมตามคณะ** แต่ทั้งสองอยู่ท้ายเมนู (ลำดับ 6–7)
- งานหลักของแอปคือ "บันทึกเซ็ตระหว่างพัก" ตอนนี้ใช้ประมาณ 8 แตะ และซ่อนอยู่ในแท็บที่ 2 ของหน้าที่ 2

ภาพหน้าจอที่ใช้ตรวจมี 14 ภาพ (7 หน้า × desktop 1280 / mobile 390)

**ผลการตัดสินใจของเจ้าของ (2026-10-17):**

| เรื่อง | เลือก |
|---|---|
| ทิศทางภาพ | **B "ยิมกลางคืน"** |
| ขอบเขต | **ทำครบเฟส 0–4** |
| เมนู | **แถบล่าง 5 ช่อง** (วันนี้ / บันทึก / ชาเลนจ์ / อันดับ / ฉัน) |

## 3. ปัญหาตามลำดับความสำคัญ

### P0: ต้องแก้ก่อน

1. **บันทึกเซ็ตช้าและซ่อนลึก**
   - ปัญหา:
     - หน้าเวทเปิดมาที่คลังท่า 30 การ์ด
     - ฟอร์มเป็น select กับช่องตัวเลขเปล่า แล้วต้องกดบันทึก Session ซ้ำอีกรอบ
   - วิธีแก้:
     - หน้า "วันนี้" ดึงท่าจากแผนหรือครั้งล่าสุดมาให้เลย
     - ปุ่ม +/- ขนาด ≥48px สำหรับ kg และ reps
     - ปุ่มเดียว "✓ เซ็ตเสร็จ" ที่เริ่มนับเวลาพักไปด้วย
     - บันทึก session อัตโนมัติ
2. **ปุ่มเล็กและไม่มีโฟกัส**
   - ปัญหาปุ่ม:
     - `.btn-sm` สูงประมาณ 28px และใช้ 42 ที่ รวมปุ่ม ✕ ลบ
     - เมนูมือถือสูงประมาณ 28–30px
     - `.modal-close` สูงประมาณ 27px
     - แท็บสูงประมาณ 34px
   - ปัญหาโฟกัส:
     - `input,select{outline:none}`
     - ปุ่มไม่มี `:focus-visible`
   - วิธีแก้: ปุ่มสูงขั้นต่ำ 44px (ปุ่มที่ใช้ระหว่างออกกำลังกาย 48px) และใส่ focus ring ทั้งระบบ

### P1: กระทบทุกหน้า

3. **เมนูมือถือ 7 รายการเลื่อนแนวนอน**
   - ปัญหา: "แผนออก…" ถูกตัด, คำนวณ/ชาเลนจ์/อันดับมองไม่เห็นและไม่มีอะไรบอกว่าเลื่อนได้
   - วิธีแก้: **แถบล่าง 5 ช่อง**
     - วันนี้ (ภาพรวม + แผน)
     - บันทึก (เวท + คาร์ดิโอ)
     - ชาเลนจ์
     - อันดับ
     - ฉัน (โปรไฟล์, เครื่องคำนวณ, นาฬิกา, สำรองข้อมูล)
4. **ลำดับความสำคัญกลับหัว**
   - ปัญหา: ปุ่มขาว "⌚ เชื่อมนาฬิกา" เด่นที่สุดทุกหน้า ขณะที่หน้าแรกมี CTA 3 สีแข่งกัน
   - วิธีแก้:
     - นาฬิกาเหลือเป็นไอคอนสถานะเล็กๆ
     - แต่ละหน้ามี action หลักได้แค่ 1 อย่าง
5. **สีไม่มีความหมาย และคอนทราสต์ปุ่มต่ำ**
   - ปัญหา:
     - สีแดงใช้หลายความหมายพร้อมกัน: แบรนด์, CTA, อก, BMR, ลบ, ยกเลิกการเชื่อมต่อ
     - คอนทราสต์ปุ่มต่ำ:

       | สี | อัตราส่วน |
       |---|---|
       | ขาวบนส้ม `#fb8c00` | 2.37 |
       | ขาวบนเขียว `#43a047` | 3.30 |
       | ขาวบนแดง `#e53935` | 4.23 |
       | ฟ้า `#1565c0` เมื่อใช้เป็นตัวอักษร | 2.7–3.0 |

   - วิธีแก้:
     - accent สำหรับ action มีสีเดียว
     - สีแดงใช้เฉพาะลบ/error
     - ตัวเลขเป็นสีกลาง ส่วนที่เปลี่ยน (delta) ค่อยใส่สี
     - สีกล้ามเนื้อใช้เฉพาะ tag
6. **ตัวอักษรไทย**
   - ปัญหา:
     - ไม่มีฟอนต์ไทย และไม่ได้ตั้ง line-height (ค่าเริ่มต้นประมาณ 1.2) สระ/วรรณยุกต์จึงชนกัน
     - ตารางบนมือถือตัดคำกลางพยางค์ ("วิด/พื้น", "ส/ควอท")
     - ขนาดตัวอักษรมีประมาณ 20 ค่า
   - วิธีแก้:
     - ใช้ฟอนต์ไทยจริง เช่น IBM Plex Sans Thai, Anuphan หรือ Noto Sans Thai
     - line-height ไทย 1.6
     - type scale 6 ขั้น
     - บนมือถือเปลี่ยนตารางเป็นแถวการ์ด

### P2: ควรแก้

7. **คอนทราสต์ข้อความรอง**
   - ปัญหา:
     - `#888` บน `#242424` ได้ 4.38 และใช้ที่ขนาด 0.72–0.8rem
     - เส้นขอบ `#333` บน `#1a1a1a` ได้ 1.38
   - วิธีแก้: ข้อความรองใช้ประมาณ `#a8a8a8` ขนาด ≥0.85rem และ placeholder เขียนแบบ "เช่น 60"
8. **สถานะว่าง/ข้อมูลเพี้ยน**
   - ปัญหา:
     - กราฟว่างเหลือแต่แกน
     - "≈0 kcal"
     - การ์ดสถิติแสดง "-"
     - หน้าแรกขึ้น "0 แคลอรี่" ขัดกับแถวที่เขียน ≈210
   - วิธีแก้: ออกแบบ empty state ที่มี CTA 1 ปุ่ม, ไม่รู้ค่าก็ซ่อนแทนการแสดง 0 และใช้สูตรแคลอรี่เดียวกันทั้งระบบ
9. **ไม่รองรับ `prefers-reduced-motion`** (hover ยกการ์ด, หัวใจเต้น, ปุ่ม scale)
10. **ARIA**
    - ปัญหา:
      - แท็บไม่มี `role="tab"`/`aria-selected`
      - กราฟ canvas ไม่มีข้อความแทน
      - สถานะใช้ emoji ล้วน (⏳ ✅ 📤 🚩)
    - วิธีแก้: ใส่ role/aria ให้ครบ, ใส่ข้อความแทนกราฟ และให้สถานะมีข้อความกำกับ

### P3: เก็บงาน

- ระบบ token ไม่เป็นระเบียบ:

  | สิ่งที่นับ | จำนวน |
  |---|---|
  | token | 12 |
  | hex ที่ใช้จริง | 52 |
  | inline style | 176 |
  | radius | 10 แบบ |
  | spacing | ประมาณ 50 ค่า |

- Chart.js (206 KB) โหลดใน `<head>` และบล็อกการแสดงผล ควรเปลี่ยนเป็น `defer` หรือโหลดเมื่อเปิดหน้าที่มีกราฟ
- Breakpoint มีแค่ 768px จุดเดียว
- ปุ่ม Export/Import อยู่ใน hero หน้าแรก ควรย้ายไปที่ "ฉัน"
- ฟอร์ม BMR ถามเพศ/อายุ/น้ำหนัก/ส่วนสูงซ้ำกับโปรไฟล์ ส่วน "Maintain" ก็ซ้ำกับ TDEE
- หน้าอันดับรวม 3 อย่างไว้ในหน้าเดียว คือบัญชีตัวเอง, ข้อมูลสาธารณะ และคิวผู้ดูแล ควรแยกคิวผู้ดูแลไปหน้าของตัวเอง

## 4. ผู้ใช้ 3 แบบที่ติดปัญหา

- **มือใหม่ ใช้มือถือในยิม**
  - เข้ามาเจอ 0/0/0/0 และกราฟว่าง
  - ไม่รู้ว่า RIR/TDEE คืออะไร
  - แตะแผน "Bench Press 4×8" แล้วไม่มีอะไรเกิดขึ้น
  - หาชาเลนจ์/อันดับไม่เจอ
- **ผู้ใช้ประจำ อยากบันทึกเร็ว**
  - ไม่มีน้ำหนักครั้งก่อนให้
  - ต้องพิมพ์ด้วยคีย์บอร์ดทุกเซ็ต
  - ต้องบันทึก 2 ชั้น
  - บนมือถือนาฬิกาพักหลุดไปอยู่ใต้จอ
- **สายตาไม่ดี / ใช้คีย์บอร์ด**
  - ตัวเทาเล็ก 12–13px
  - ไม่มี focus ring
  - สถานะเป็น emoji ล้วน
  - ปุ่ม ✕ ไม่มีข้อความกำกับ

## 5. แผนปรับ (แบ่งเฟส)

### เฟส 0: ตั้งทิศทาง (ประมาณ 0.5 วัน, ต้องคุยกับเจ้าของ)

- `impeccable init` เขียน `PRODUCT.md` ซึ่งระบุ
  - กลุ่มผู้ใช้: นักศึกษา มรภ., มือใหม่
  - งานหลัก: บันทึกเซ็ต, แข่งกับเพื่อน
  - โทน
  - ข้อห้าม
- เลือกทิศทางภาพ 1 จาก 2–3 แนว (เป็น mock ภาพนิ่ง) แล้วเขียน `DESIGN.md`
- โหมด: **Operate** คือแอปทำงาน เน้นอ่านเร็ว, ใช้มือเดียว, และยังใช้ได้ตอนเหงื่อออก
- แนวที่เสนอให้เลือก:
  - **A "สมุดโค้ช"**: พื้นสว่างอุ่น, ตัวเลขใหญ่ mono, accent สีเดียว (คล้ายสไลด์นำเสนอที่ทำไว้)
  - **B "ยิมกลางคืน"**: ยังเป็น dark แต่เป็นกลางขึ้น (ไม่ดำสนิท), accent เดียวสีสด, ตัวเลขเป็นพระเอก
  - **C "สนามคณะ"**: เน้นการแข่ง ใช้สีของทีม/คณะ, อันดับและคู่ดวลเด่นที่หน้าแรก

### เฟส 1: รากฐาน (ประมาณ 1–1.5 วัน)

- **Design tokens**
  - สี: bg, surface ×3, text ×3, accent, success, warn, danger, muscle ×6
  - spacing 4/8 ขั้น
  - radius 3 ค่า
  - shadow 2 ค่า
  - motion 2 ค่า
- **ฟอนต์ไทย** (self-host หรือ Google Fonts พร้อม `font-display:swap`), type scale 6 ขั้น, line-height ไทย 1.6
- **กฎพื้นฐานทั้งระบบ**
  - ปุ่ม ≥44px
  - `:focus-visible` ring
  - `prefers-reduced-motion`
  - คอนทราสต์ AA ทุกคู่
- **ย้าย inline style ไปเป็นคลาส**
  - เป้าหมาย < 20 จุด
  - หลัก hex ที่ใช้จริงต้องอ้าง token เท่านั้น
- **Chart.js** ใช้ `defer`

### เฟส 2: โครงนำทาง (ประมาณ 1 วัน)

- มือถือใช้แถบล่าง 5 ช่อง ส่วน desktop ใช้ sidebar หรือ top bar 5 ช่อง
- โครงใหม่:

  | ช่อง | ข้างในมี |
  |---|---|
  | วันนี้ | สรุป + แผนวันนี้ + อันดับเทียบเพื่อน |
  | บันทึก | เวท / คาร์ดิโอ |
  | ชาเลนจ์ | กล้อง |
  | อันดับ | อันดับ + การแข่ง |
  | ฉัน | โปรไฟล์, คำนวณ, นาฬิกา, Strava, สำรองข้อมูล, ผู้ดูแล |

- นาฬิกาเหลือเป็นไอคอนสถานะบน header
- route เดิม (`showPage`) ยังใช้ได้ (ทำ map ชื่อเก่าไปชื่อใหม่) เพื่อไม่ให้เทส e2e เดิมพัง

### เฟส 3: หน้าหลัก (ประมาณ 3–4 วัน, เรียงตามความสำคัญ)

1. **บันทึกเวท**
   - การ์ดท่าปัจจุบัน
   - ปุ่ม +/- (kg, reps, RIR)
   - ปุ่ม "✓ เซ็ตเสร็จ" ที่เริ่มนับพักให้เอง
   - แสดงครั้งก่อน/PR
   - ปุ่ม "ทำซ้ำครั้งก่อน"
   - บันทึกอัตโนมัติ
   - หน้าสรุปจบ session (volume เทียบครั้งก่อน, PR ใหม่, streak)
   - คลังท่ากลายเป็นแผ่นค้นหาที่เปิดจากปุ่ม "เปลี่ยนท่า"
2. **วันนี้ (หน้าแรก)**
   - แผนวันนี้กดแล้วเริ่มบันทึกได้เลย
   - KPI 2×2
   - empty state พร้อม CTA เดียว
   - กราฟที่มีข้อมูลจริงหรือซ่อนไป
   - การ์ดอันดับ/ดวลที่กำลังแข่ง
3. **ชาเลนจ์**
   - preview กล้องเป็น hero
   - ปุ่มเริ่ม 1 ปุ่มใหญ่
   - ตัวนับใหญ่พร้อมสถานะท่าถูก/ผิดที่มีข้อความกำกับ
   - ฉลองเมื่อทำลายสถิติ
   - ประวัติเป็นแถวการ์ด
4. **อันดับ**
   - ตัวกรองรวมเป็น chips 2 แถว (ช่วงเวลา และท่า) ส่วนเพศ/อายุอยู่ใน "ตัวกรองเพิ่ม"
   - แถวอันดับเป็นการ์ดเตี้ย โดย "ฉัน" ติดอยู่ล่างจอ
   - การแข่งย้ายไปแท็บของตัวเอง
   - ฟอร์มสร้างดวล/ทีม/อีเวนต์รวมเป็นปุ่มเดียว "+ สร้างการแข่ง" ที่เปิด sheet
5. **คาร์ดิโอ**
   - ฟอร์มขึ้นก่อน Strava
   - การ์ด Strava ย่อเป็นแถบสถานะ
   - ปุ่มตัดการเชื่อมต่อย้ายไป "ฉัน"
6. **ฉัน**
   - โปรไฟล์ครั้งเดียวแล้วเครื่องคำนวณดึงไปใช้
   - คำนวณเป็นคำตอบสั้น ไม่ต้องมี 6 การ์ดสีรุ้ง
   - คิวผู้ดูแลแยกไว้ในส่วนนี้

### เฟส 4: ความรู้สึก + ตรวจ (ประมาณ 1 วัน)

- **Onboarding 3 ขั้น**: เลือกเป้าหมาย, กรอกโปรไฟล์, เลือกโปรแกรม แล้วระบบสร้างแผนให้
- **ศัพท์ไทยพร้อมคำอธิบาย**: กดที่ RIR/TDEE/Volume แล้วมีคำอธิบายสั้นขึ้นมา
- **ลบแบบมี undo**: แจ้งเตือนว่า "ลบแล้ว · เลิกทำ" แทนการลบทันที
- **ตรวจ**:
  - critique ใหม่ (เป้าหมาย ≥32/40)
  - detector ต้องได้ 0 warning
  - เทส e2e เดิม 130+ ผ่านหมด
  - ภาพหน้าจอใหม่สำหรับเล่ม

**รวมประมาณ 7–9 วันทำงาน** ทำทีละเฟส แต่ละเฟสต้องผ่านเทสทั้งหมด และ deploy แยกกันได้

## 6. สิ่งที่ไม่เปลี่ยน

- ข้อมูลใน localStorage (`schemaVersion 2`) และ API `/api/social`, `/api/strava`
- ฟีเจอร์ทั้งหมด (ไม่ตัดอะไรออก ย้ายที่อย่างเดียว)
- ไฟล์เดียว `index.html` (เว้นแต่ตกลงกันว่าจะแยก CSS)
- PWA / service worker (bump cache เมื่อ deploy)

## 7. ความเสี่ยง

- **เทส UI เดิมผูกกับ id/โครงหน้า**: เก็บ id เดิมไว้ หรือแก้เทสไปพร้อมกันในเฟสเดียวกัน
- **ภาพในเล่มโครงงานจะไม่ตรงกับของจริง**: ถ่ายภาพใหม่หลังเฟส 3
- **ฟอนต์เว็บทำให้โหลดช้าลง**: โหลดเฉพาะน้ำหนัก 400/600/700 แบบ subset ไทย+ละติน
