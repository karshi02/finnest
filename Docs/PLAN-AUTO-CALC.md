# แผน: ให้แอปคำนวณอัตโนมัติ

วันที่: 2026-10-15
สถานะ: **ร่างแผน ยังไม่ได้ลงมือ** รอเลือกว่าจะทำข้อไหน

## 1. ตอนนี้อะไรที่ผู้ใช้ยังต้องกรอกหรือคิดเอง

ตรวจจาก `index.html` ปัจจุบัน:

| จุด | ตอนนี้ | ปัญหา |
|---|---|---|
| แคลอรี่เวทเทรนนิ่ง | `cals: 0` ทุก session | การ์ด "🔥 แคลอรี่เผา" ในหน้าภาพรวมนับแค่คาร์ดิโอ จึงต่ำกว่าจริง |
| แคลอรี่คาร์ดิโอ | ต้องพิมพ์เอง | มือใหม่ไม่รู้ว่าควรใส่เท่าไร มักเว้นว่าง (= 0) |
| ระดับความเข้มคาร์ดิโอ | เลือกเองจาก dropdown | มี HR เฉลี่ยอยู่แล้วแต่ไม่ได้ใช้ (ยกเว้นรายการที่มาจาก Strava) |
| Pace | ต้องไปกรอกซ้ำในการ์ด "คำนวณ Pace" | ไม่แสดงในประวัติ |
| เครื่องคำนวณ BMR / BMI / มาโคร | ต้องพิมพ์อายุ น้ำหนัก ส่วนสูงใหม่ทุกครั้ง | โปรไฟล์เก็บแค่อายุกับ HR พัก |
| 1RM | ต้องพิมพ์น้ำหนักและจำนวนครั้งเอง | มีข้อมูลทุก set ในประวัติอยู่แล้ว |
| ความก้าวหน้า | ไม่มี | ไม่รู้ว่าครั้งนี้ทำลายสถิติเดิมไหม หรือครั้งหน้าควรเพิ่มน้ำหนักเท่าไร |
| นาฬิกาพัก | ต้องกดเริ่มเองหลังบันทึก set | |

## 2. สิ่งที่คำนวณอัตโนมัติได้

### กลุ่ม A: ใช้ข้อมูลที่มีอยู่แล้ว ไม่ต้องถามผู้ใช้เพิ่ม

| ID | ฟีเจอร์ | วิธีคำนวณ | แสดงตรงไหน |
|---|---|---|---|
| A1 | **ระดับความเข้มจาก HR** | HR เฉลี่ย + โซน Karvonen จาก `state.profile` (มีฟังก์ชัน `stravaIntensity()` แล้ว) เลือก dropdown ให้เองเมื่อกรอก HR หรือกด "บันทึกเป็นคาร์ดิโอ" | ฟอร์มบันทึกคาร์ดิโอ |
| A2 | **Pace / ความเร็ว** | วิ่ง/เดิน: นาที ÷ กม. (นาที/กม.), ปั่น: กม. ÷ ชม. | คอลัมน์ใหม่ในประวัติคาร์ดิโอ และแสดงสดใต้ฟอร์มตอนกรอก |
| A3 | **1RM โดยประมาณรายท่า** | Epley/Brzycki เหมือนเครื่องคำนวณเดิม ใช้ set ที่ reps ≤ 10 ที่ดีที่สุดของแต่ละท่า | การ์ดท่าในคลังท่า + กราฟความก้าวหน้ารายท่า |
| A4 | **สถิติส่วนตัว (PR)** | ตอนบันทึก set: เทียบน้ำหนักสูงสุด, e1RM, volume ของท่านั้นกับประวัติ | toast "🏆 สถิติใหม่! Bench Press 45 kg" และป้าย PR ในประวัติ |
| A5 | **แนะนำน้ำหนักครั้งหน้า** (Progressive Overload) | ครั้งก่อนทำครบทุก set และ RIR ≥ 2 → แนะนำ +2.5 kg (ช่วงบน) / +5 kg (ขา); ถ้า RIR 0 หรือทำไม่ครบ → คงเดิม | เติมให้ในช่องน้ำหนักเมื่อเลือกท่า พร้อมข้อความเหตุผล |
| A6 | **สรุปรายสัปดาห์** | นาทีคาร์ดิโอเทียบเป้า WHO 150 นาที/สัปดาห์, จำนวนวันฝึก, set ต่อกลุ่มกล้ามเนื้อ, ฝึกติดต่อกันกี่สัปดาห์ (streak) | การ์ดใหม่ในหน้าภาพรวม |
| A7 | **เตือนกล้ามเนื้อที่ขาด** | กลุ่มที่ไม่ได้ฝึกเกิน 7 วัน | ข้อความในการ์ดสรุปรายสัปดาห์ |
| A8 | **เวลาในแต่ละโซนหัวใจ** | ระหว่าง stopwatch + นาฬิกาเชื่อมอยู่ นับวินาทีในแต่ละโซน | แถบโซนใต้ HR สด และบันทึกลงรายการคาร์ดิโอ |
| A9 | **เริ่มนาฬิกาพักเอง** | หลังกด "บันทึก Set" เริ่มนับถอยหลังตามเวลาที่ตั้งล่าสุด (เปิด/ปิดได้) | การ์ดนาฬิกาพัก |

### กลุ่ม B: ต้องเก็บโปรไฟล์เพิ่ม 3 ช่อง (เพศ, น้ำหนัก, ส่วนสูง) ครั้งเดียว

| ID | ฟีเจอร์ | วิธีคำนวณ | แสดงตรงไหน |
|---|---|---|---|
| B0 | **โปรไฟล์** | เพิ่ม `sex`, `weight`, `height` ใน `state.profile` (มี `age`, `rhr` อยู่แล้ว) | ฟอร์มโปรไฟล์เดียว เช่น ปุ่ม 👤 บนแถบด้านบน |
| B1 | **แคลอรี่คาร์ดิโออัตโนมัติ** | มี HR เฉลี่ย: สูตร Keytel และคณะ (2005); ไม่มี HR: MET × น้ำหนัก × ชั่วโมง (Compendium of Physical Activities) | เติมในช่อง kcal ถ้าเว้นว่าง พร้อมป้าย "≈ ประมาณ" |
| B2 | **แคลอรี่เวทเทรนนิ่ง** | MET (3.5 ปานกลาง / 6 หนัก ตาม RIR เฉลี่ย) × น้ำหนัก × ระยะเวลา session (จากเวลา set แรกถึง set สุดท้าย + 2 นาที) | `session.cals` → การ์ดแคลอรี่ในหน้าภาพรวมนับเวทด้วย |
| B3 | **เติมเครื่องคำนวณให้เอง** | BMR/TDEE, BMI, มาโคร ใช้ค่าจากโปรไฟล์ และคำนวณทันทีเมื่อเปิดแท็บ | หน้าคำนวณ |
| B4 | **บันทึกน้ำหนักตัว + แนวโน้ม** | น้ำหนักตัวรายวัน → ค่าเฉลี่ย 7 วัน, เปลี่ยนแปลงต่อสัปดาห์ | กราฟเล็กในหน้าภาพรวม |
| B5 | **พลังงานคงเหลือวันนี้** | TDEE + แคลอรี่ที่เผาวันนี้ (B1+B2) | การ์ดในหน้าภาพรวม |

**สูตรที่จะใช้ (ตรวจกับต้นฉบับอีกครั้งตอนลงมือ):**
- Keytel และคณะ (2005), *J Sports Sci* 23(3): 289–297 (kcal/นาที, W = กก., A = ปี):
  - ชาย: `(−55.0969 + 0.6309·HR + 0.1988·W + 0.2017·A) / 4.184`
  - หญิง: `(−20.4022 + 0.4472·HR − 0.1263·W + 0.074·A) / 4.184`
- MET: Compendium of Physical Activities ใช้ค่าเฉลี่ยของแต่ละประเภท เช่น วิ่ง ≈ 9.8, ปั่น ≈ 7.5, เดินเร็ว ≈ 4.3, ว่ายน้ำ ≈ 7, เชือกกระโดด ≈ 11, HIIT ≈ 8, เวท ≈ 3.5–6

ค่าที่ได้เป็น**ค่าประมาณ** (คลาดเคลื่อนได้ราว ±20%) จะติดป้าย "≈" ทุกที่ และผู้ใช้แก้เองทับได้เสมอ

### กลุ่ม C: ยังไม่แนะนำตอนนี้

| ฟีเจอร์ | เหตุผล |
|---|---|
| ประมาณ VO₂max / ความฟิต | ต้องใช้ข้อมูลวิ่งที่มี HR + pace สม่ำเสมอ และสูตรคลาดเคลื่อนสูงสำหรับมือใหม่ |
| ประมาณ HR สูงสุดจริงจากข้อมูล | ต้องรอข้อมูลหลายสัปดาห์ ทำได้หลัง A8 |
| แนะนำโปรแกรมฝึกทั้งสัปดาห์อัตโนมัติ | งานใหญ่ ควรรอให้ A5–A7 ใช้จริงก่อน |

## 3. ลำดับที่แนะนำ

เรียงจากคุ้มที่สุดสำหรับมือใหม่ (ได้ผลเยอะ งานน้อย):

| รอบ | งาน | ขนาด | ได้อะไร |
|---|---|---|---|
| **1** | A1, A2, A9 | เล็ก (ประมาณ 1–2 ชม.) | กรอกน้อยลงทันที ไม่ต้องเพิ่มข้อมูล |
| **2** | B0, B1, B2, B3 | กลาง (ประมาณ 3–4 ชม.) | แคลอรี่ครบทั้งเวทและคาร์ดิโอ ตัวเลขหน้าภาพรวมถูกต้อง เครื่องคำนวณไม่ต้องพิมพ์ซ้ำ |
| **3** | A3, A4, A5 | กลาง (ประมาณ 3–4 ชม.) | เห็นความก้าวหน้า สถิติใหม่ และรู้ว่าครั้งหน้าควรยกเท่าไร (ช่วยมือใหม่มากที่สุด) |
| **4** | A6, A7, A8, B4, B5 | กลาง–ใหญ่ (ประมาณ 4–6 ชม.) | สรุปรายสัปดาห์ เตือนกล้ามที่ขาด เวลาในโซน น้ำหนักตัว |

ทุกรอบ: เพิ่มชุดทดสอบอัตโนมัติ (ค่าคำนวณเทียบกับการคิดมือ), รันชุดเดิม 72 ข้อ, เพิ่ม cache ของ `sw.js`, deploy, เขียนรายงาน

## 4. ผลกระทบต่อข้อมูลเดิม

- เพิ่มฟิลด์ใหม่แบบไม่บังคับ (`profile.sex/weight/height`, `cardio.kcalEst`, `cardio.zoneSecs`, `session.cals`) ข้อมูลเก่าใช้ได้ต่อ ไม่ต้องย้ายข้อมูล
- session เก่าที่ `cals: 0` จะคำนวณย้อนหลังได้ถ้ามีเวลาของ set (มี `ts` ทุก set อยู่แล้ว) จะถามก่อนคำนวณย้อนหลัง
- ไฟล์ Export/Import รองรับฟิลด์ใหม่ (ต้องเพิ่มใน `importData()` และ `normalizeState()`)

## 5. เรื่องที่ต้องตัดสินใจก่อนเริ่ม

| เรื่อง | ตัวเลือก | แนะนำ |
|---|---|---|
| จะทำรอบไหน | 1 / 1+2 / 1–3 / ทั้งหมด | **รอบ 1 + 2** ก่อน แล้วค่อยตัดสินใจรอบ 3 |
| แคลอรี่อัตโนมัติ | เติมให้เองเมื่อเว้นว่าง / แสดงเป็นคำแนะนำให้กดใส่ | **เติมให้เองเมื่อเว้นว่าง** ติดป้าย ≈ |
| แนะนำน้ำหนักครั้งหน้า | เติมในช่องให้เลย / แสดงเป็นข้อความเฉย ๆ | **แสดงเป็นข้อความ + ปุ่ม "ใช้ค่านี้"** มือใหม่จะได้ตัดสินใจเอง |
| เริ่มนาฬิกาพักเอง | เปิดเป็นค่าเริ่มต้น / ปิด | **เปิด** และมีสวิตช์ปิด |
| คำนวณแคลอรี่ย้อนหลังให้ session เก่า | ทำ / ไม่ทำ | **ถามผู้ใช้ครั้งเดียว** |
